# Brainstorm: Hub & Spoke Terminal UX

## Initial Problem Statement

터미널에서 여러 태스크를 동시에 작업할 때의 UX 개선. 현재 tmux 패널 분할로 작업 중이나 한계가 있음.

## Discovery Journey

### 현재 워크플로우 분석
- **방식**: tmux 패널 분할 + 각 패널에서 독립 Claude 세션
- **장점**: 간단함, 병렬 작업, 한눈에 파악
- **단점**:
  1. worktree 생성이 번거로움
  2. 파일 열람 불가
  3. 패널 많아지면 너무 작아짐

### 핵심 요구사항
- 완벽한 격리 (worktree 기반)
- 빠른 전환
- 상태 보존
- 상호 참조는 불필요
- 여러 패널처럼 개요 확인 + 필요시 파일 접근

### 접근법 탐색
1. **TUI 대시보드**: Claude Code에 TUI 모드 추가 → 패널 크기 조절 한계
2. **tmux 자동화 CLI**: 기존 방식 + worktree 자동화 → 탈락
3. **Hub & Spoke**: 대시보드 허브 + 독립 터미널들 → 선택

## Root Problem

> "터미널에서 여러 태스크를 동시에 돌릴 때, 전체 상태를 파악하면서도 각 태스크에 충분한 화면 공간을 확보하는 방법이 없다"

TUI의 한계 (패널 크기 조절)와 현재 방식의 한계 (패널 과다)를 동시에 해결해야 함.

## Solution: Hub & Spoke Architecture

### 개념

```
┌─────────────────────────────────────────────────────────┐
│                 Hub (TUI 대시보드)                       │
│  ┌─────────────────┐  ┌─────────────────────────────┐  │
│  │ [Active]        │  │ [File Viewer]               │  │
│  │ ● task-1 🔔     │  │ src/auth.ts (task-1)        │  │
│  │ ● task-2        │  │ 15: const token = ...       │  │
│  │                 │  │ 16: → [marked]              │  │
│  │ [Background]    │  │ 17: return { token }        │  │
│  │ ○ task-3 (5m)   │  │                             │  │
│  │ ○ task-4 done ✓ │  │ [Comments] (2)              │  │
│  │ ○ task-5 run    │  │ ● L16: 이 계산 맞나?        │  │
│  └─────────────────┘  └─────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘

+ 별도 터미널 창들 (Active만)
┌─────────────┐  ┌─────────────┐
│   Task 1    │  │   Task 2    │  ← OS 레벨 창 크기 조절
│  (Claude)   │  │  (Claude)   │
└─────────────┘  └─────────────┘
```

### 핵심 설계

**Hub (TUI 대시보드)**
- 항상 떠 있는 상태 모니터
- 태스크 상태 표시 (Active / Background 구분)
- 파일 뷰어 통합
- 코멘트 수집 및 전송 기능

**Spoke (독립 세션)**
- 각 태스크는 독립 터미널 창
- 기존 Claude Code 그대로 사용
- OS 레벨에서 창 크기 자유롭게 조절
- 창 닫아도 태스크는 계속 실행 (headless)

**Active vs Background**
- Active: 창이 열려있는 태스크 (2-3개)
- Background: 창 없이 돌아가는 태스크 (10개+)
- Hub에서 선택하면 해당 태스크 창 열림/포커스

### 파일 뷰어 + 코멘트 기능

```
1. Hub에서 파일 확인
   │ 15:   const token = jwt.sign()    │
   │ 16: → const expired = ...         │ ← [v] 선택, [m] 마크
   │ 17:   return { token, expired }   │

2. 마크한 영역에 코멘트 추가
   │ [Comments]                        │
   │ 1. L16-17: 왜 expired 여기서?     │
   │ 2. L22: 에러 핸들링 맞나?         │
   │ [a]dd  [e]dit  [d]elete  [s]end   │

3. 코멘트를 Spoke에 전송
   > [s]end → task-1
   → Claude 세션에 자동 입력
```

**복잡도**: 중간 (영역 선택 + 코멘트 수집 + 일괄 전송)

### 알림

- Hub에서 상태 강조 (색상, 아이콘)
- OS 레벨 시스템 알림
- 둘 다 사용

## Trade-offs

| 항목 | 장점 | 단점/리스크 |
|------|------|------------|
| 패널 크기 | OS 레벨 조절로 자유로움 | 여러 창 관리 필요 |
| 격리 | 각 태스크 완전 독립 | 상태 동기화 구현 필요 |
| 확장성 | 10개+ 태스크 Background 관리 | 리소스 사용량 |
| 파일 접근 | Hub에서 모든 태스크 파일 확인 | TUI 파일 뷰어 한계 |

### 완화 방안

- **창 관리**: Hub에서 한 키로 전환
- **리소스**: 유휴 시 일시정지 옵션
- **상태 동기화**: 파일 기반 또는 IPC
- **worktree 정리**: 완료된 태스크 자동 정리
